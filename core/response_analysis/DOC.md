# Аналіз відповіді

## Призначення

`response_analysis` класифікує текстову відповідь як:

- `CONFIRMATION` — підтвердження;
- `REJECTION` — відмову;
- `UNKNOWN` — недостатньо впевнена класифікація.

Модуль лише аналізує текст. Подальшу дію визначає код асистента, який викликав аналізатор.

## Потік класифікації

`ResponseAnalyzer.analyze(question, answer, dialog_context)` передає відповідь до `DecisionEngine`. Поточний рушій не аналізує зміст `question`; з контексту він використовує список очікуваних категорій.

Порядок перевірок у `DecisionEngine.decide()`:

1. Нормалізація відповіді.
2. Перевірка фраз невизначеності (`не знаю`, `можливо` тощо); результат — `UNKNOWN`.
3. Точний збіг із патерном очікуваної категорії.
4. Перевірка одночасних маркерів підтвердження й заперечення; суперечлива відповідь класифікується як `REJECTION`.
5. Перевірка явних фраз дозволу, наприклад «можеш відкрити».
6. Частковий збіг із патерном.
7. Семантична оцінка.
8. `UNKNOWN`, якщо жодна перевірка не дала достатнього результату.

Зіставлення патернів порівнює нормалізований текст із повною фразою патерна. Частковим вважається входження одного рядка в інший. Очікувані категорії задаються через `DialogContext.expected_response_categories`; за замовчуванням це підтвердження та відмова.

`ResponseAnalysis` містить категорію, оцінку впевненості, за наявності — відповідний патерн, і джерело: `RULE`, `PATTERN`, `SEMANTIC` або `UNKNOWN`.

## Компоненти

| Файл | Призначення |
| --- | --- |
| `models.py` | Категорії, контекст діалогу, результат, кандидат на патерн і SQLAlchemy-моделі |
| `text_normalizer.py` | Нижній регістр, нормалізація апострофа, видалення `!?.` та нормалізація пробілів |
| `repository.py` | Зберігання патернів і записів рішень |
| `pattern_matcher.py` | Точний і частковий збіг із патернами |
| `decision_engine.py` | Порядок правил і вибір результату |
| `semantic_analyzer.py` | Семантична оцінка тексту |
| `response_learner.py` | Перевірка й прийняття кандидатів на нові патерни |
| `response_analyzer.py` | Публічний метод `analyze(...)` |

### Нормалізація

Нормалізація зводить великі літери й повторні пробіли до стандартного вигляду, замінює типографський апостроф на звичайний і видаляє знаки `!?.`. Вона не виконує морфологічний або інший мовний аналіз.

### Семантична оцінка

За наявності `sentence-transformers` використовується `sentence-transformers/all-MiniLM-L6-v2` і косинусна схожість векторів відповіді та збережених патернів. Модель завантажується під час першого семантичного аналізу.

Якщо модель недоступна, аналізатор переходить до спрощених бінарних векторів спільних слів. Це резервний механізм зіставлення, а не повноцінне розуміння мови.

Параметри `ResponseAnalysisConfig`:

| Параметр | Значення за замовчуванням |
| --- | ---: |
| `semantic_min_threshold` | `0.62` |
| `semantic_high_threshold` | `0.78` |
| `min_conflict_margin` | `0.08` |
| `exact_match_confidence` | `1.0` |
| `phrase_match_confidence` | `0.96` |
| `max_pattern_words` | `4` |
| `max_pattern_length` | `45` |

Семантичний результат приймається лише за високого порога й достатньої різниці з оцінкою іншої категорії. За нижчої впевненості повертається `UNKNOWN`.

## Сховище

`ResponseRepository` використовує SQLAlchemy та SQLite. Якщо `database_url` не передано, шлях береться з `settings.DATABASES["default"]["NAME"]` — у типовій конфігурації проєкту це `db.sqlite3`. Іншу адресу можна передати через `database_url`.

Під час створення репозиторію таблиці створюються, якщо їх ще немає. Відсутні базові патерни підтвердження й відмов додаються індивідуально; наявні, зокрема користувацькі, не видаляються й не дублюються.

| Таблиця | Дані |
| --- | --- |
| `response_patterns` | Фрази патернів, їхні категорії та впевненість |
| `response_confirmations` | Записані підтвердження з контекстом, кандидатом та оцінкою |
| `response_rejections` | Записані відмови з контекстом, кандидатом та оцінкою |

Таблиці створює SQLAlchemy через `Base.metadata.create_all()`. Ініціалізація репозиторію також додає відсутні базові патерни.

## Навчання патернів

`ResponseLearner.create_candidate(...)` повертає кандидата лише якщо нормалізований текст непорожній, містить не більше чотирьох слів і 45 символів та ще не збережений у репозиторії. Створення або відхилення кандидата саме по собі не змінює таблицю патернів:

- `accept_candidate(...)` додає патерн;
- `reject_candidate(...)` не зберігає патерн і повертає `True`.

У голосовому потоці асистент пропонує зберігати нову фразу, коли відповідь класифікована семантично й відповідає обмеженням кандидата. Код, який викликає learner, окремо записує відповідь користувача на пропозицію в `response_confirmations` або `response_rejections`. Тільки згода додає патерн до `response_patterns`.

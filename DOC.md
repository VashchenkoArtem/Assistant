# Технічна документація

## Межі проєкту

Поліна — настільний асистент із GUI та консольним голосовим режимом. GUI не використовує HTTP-бекенд. Локальні команди виконуються кодом застосунку; розпізнавання мовлення, синтез голосу та запити до LLM використовують зовнішні сервіси.

## Точки запуску

| Команда | Призначення |
| --- | --- |
| `python -m gui` | Запустити графічний інтерфейс |
| `python manage.py run_assistant` | Запустити голосовий режим у терміналі |
| `python manage.py migrate` | Створити або оновити Django-таблиці |

## Архітектура виконання

| Компонент | Відповідальність |
| --- | --- |
| `gui/main_window.py` | Стан головного вікна, навігація між чатом і сторінками налаштувань, обробка введення |
| `gui/workers.py` | Фонові задачі ініціалізації, команд і голосового введення |
| `core/management/commands/run_assistant.py` | Ініціалізація асистента, маршрутизація команд і керування діями |
| `utils/list_apps.py` | Пошук установлених програм |
| `utils/match_app.py` | Пошук і зіставлення назв програм |
| `utils/voicing_answer.py` | Розпізнавання стану голосового відтворення та синтез відповідей |
| `core/response_analysis/` | Класифікація підтверджень, відмов і невизначених відповідей |
| `utils/llm_client.py`, `utils/llm_config.py` | Запити до LLM та локальна конфігурація провайдерів |

GUI використовує `QThreadPool`, щоб ініціалізація, команди й запис з мікрофона не блокували потік інтерфейсу. Текстові команди передаються в `Command.process_recognized_command`; голосові команди проходять розпізнавання з локаллю `uk-UA`.

## Маршрутизація команд

1. Асистент обробляє незавершений діалог: підтвердження, уточнення назви або вибір зі списку.
2. Локальні команди виконують дії з програмами, файлами та Провідником.
3. У текстовому чаті лише повідомлення з префіксом `/ai` передаються до LLM. Інші повідомлення обробляються як команди асистента.
4. Результат класифікації відповіді сам по собі не запускає дію. Рішення про дію приймає викликач у `run_assistant.py`.

Невизначена відповідь під час очікування підтвердження не повинна автоматично виконувати дію. Скасування обробляється окремо від звичайного підтвердження.

## Голосове введення й озвучення

- Розпізнавання виконується через `SpeechRecognition` та Google Speech Recognition (`uk-UA`).
- Перед прослуховуванням асистент калібрує розпізнавач за навколишнім шумом. Типова максимальна тривалість фрази — 5 секунд.
- Голосові відповіді генеруються через Edge TTS з українським голосовим профілем і відтворюються через `pygame`.
- Під час озвучення мікрофон продовжує слухати; нова команда може перервати поточне відтворення.
- У GUI сторінка налаштувань дає змогу вибрати мікрофон, вихідний пристрій і гучність. Значення зберігаються через Qt `QSettings`. Налаштування мікрофона застосовується до GUI; консольний режим використовує системний пристрій за замовчуванням.

## Інтеграція LLM

Вбудовані провайдери — Groq та Google Gemini. Також підтримуються власні OpenAI-сумісні API й Anthropic Messages API. Запит маршрутизується за порядком провайдерів, заданим у «Персоналізації»; за потреби використовується перехід до наступного провайдера.

| Дані | Розташування |
| --- | --- |
| Налаштування провайдерів, моделей і порядку | `.llm_preferences.json` |
| API-ключі | `.llm_credentials.json` |

Ці файли зберігаються локально та ігноруються Git. Файл ключів не шифрується. Ключі також можна передавати через змінні середовища: `GROQ_API_KEY`, `GEMINI_API_KEY`, їхні нумеровані варіанти та сумісний псевдонім `LLM_API_KEY` для Groq. Для інших провайдерів використовується `LLM_<PROVIDER_ID>_API_KEY`.

Зовнішні API викликаються з тайм-аутом 20 секунд. Тимчасова помилка мережі або сервера отримує одну повторну спробу; після повторної помилки провайдер відкладається на 45 секунд. HTTP 429 відкладає конкретний ключ на 90 секунд. Невалідні ключі пропускаються до зміни конфігурації або перезапуску процесу.

## Дані й сховища

- Django використовує SQLite-файл `db.sqlite3` для своїх моделей, зокрема реєстру програм `AppCommand`.
- `ResponseRepository` за замовчуванням використовує шлях до бази з `DATABASES["default"]["NAME"]` і створює SQLAlchemy-таблиці аналізатора в цій базі. Окремий шлях можна передати через `database_url`.
- Аналізатор зберігає патерни та записи підтверджень/відмов; деталі наведені в [документації response analyzer](./core/response_analysis/DOC.md).
- Налаштування аудіо зберігаються через системний механізм Qt `QSettings`.

## Обмеження та перевірки

- Інтеграція з Провідником і програмами Microsoft Store призначена для Windows.
- Для розпізнавання мовлення, синтезу голосу й LLM потрібне мережеве з’єднання.
- Тести запускаються командою `python -m pytest -q`.
